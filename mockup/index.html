What's real here, and what's simulated

Real: the gate map, materials, colours, EndlessSpool groups, selector offsets, bowden length, per-gate statistics and maintenance counters all come from this printer's mmu_vars.cfg. The state fields, enums and G-code shown are Happy Hare's own (filament_pos 0–10, gate_status −1/0/1/2, MMU_GATE_MAP, MMU_TTG_MAP). The error dialog is rendered from the exact action:prompt_* lines _MMU_ERROR_DIALOG emits.

Simulated: everything moves on a scripted timeline in the browser. No printer is connected, no G-code is sent, and the plugin itself does not exist yet.

Compact layout: the second layout option redraws the panel the way it would appear in this printer's own UI Customizer setup — the red-night palette (--accent #d32f2f on #1e1e20), icon-only tabs, fluid layout and a tighter density. The real plugin would take those colours from the theme's CSS variables rather than hard-coding them, and switch density from body.UICResponsiveMode and its own container width.

The point: on this machine an MMU error currently cancels the print, because OctoPrint treats Happy Hare's !! line as a firmware error, and Happy Hare's recovery dialog is never shown. The failure scenario shows what the plugin would do instead.
